## 〇、本轮核心突破：找到并修复"缺口永不探索"的四层级联缺陷

第 1 轮修了"发动机构造错误 + 队列假话"，重启后**仍不探索**。深挖发现根本不是一个 bug，
而是**四层独立缺陷叠加**成一条"感知到自己不知道、却永远不行动"的完整死链。逐层击破：

### 第 1 层：DreamAgent tick 永不返回（真正发动机故障）

- **症状**：DreamDaemon 09:15 起一次 tick，65 分钟后仍无第二次（interval=1800s）
- **实测**：`py-spy` 显示线程卡在 `epoll_wait`；首个 tick 的 I/O 从未返回
- **根因**：Phase2 O(n²) 全量两两相似度（3310 节点 → ~694k 对）+ Phase4 O(orphans × candidates)（5×1178≈5890 对 × 每对 2 embed + 2 LLM）**无工作量上界**
- **修复**：Phase2 取 quality 前 200；Phase4 每 orphan 最多扫 40 候选（`a9ebe0c`）
- **验证**：`generated 0 topics in 118147ms` → 正常返回并进入下轮（修复前：卡死）

### 第 2 层：概念去重跨域误合并（最隐蔽）

- **症状**：真实缺口 `graph neural network` 被 `dedup-skipped`，永不探索
- **根因**：`concept_normalizer` 翻译映射含**单字概念** `'图'`。反向映射按英文 token 匹配 →
  `graph neural network` 与 `知识图谱` 都提取出 `['图']` → overlap=1.0 → 判 `translated_concept`
  → 去重跳过 → **永不探索**（认知不诚实：拿"知识图谱"顶包"图神经网络"）
- **实测误判**：`edge computing ≈ 边` / `system prompt ≈ 系统` / `Graph RAG ≈ 图数据库`
- **修复**：移除全部单字与超通用概念词（图/边/层/系统/模型/数据/接口/算法/方法/技术/应用）（`8ad2ebd`）
- **保留**合法模糊匹配：`attention mechanism ≈ 注意力`（attention 确实 = 注意力）

### 第 3 层：冲突降权 = 实质否决（闸门死区）

- **症状**：`FlashAttention`（real_seen=1）永不入队
- **根因**：`rank_gaps` 先 conflict 降权（weak ×0.8）再 `>= thr` 过闸门。单次观测 value=0.80，
  ×0.8=0.64 < thr(0.7) → 静默丢弃。**弱冲突是"source split"（证据），不该否决**（CA2.0 公理B）
- **修复**：闸门用**降权前** value（决定值不值得探索），降权后 value 只参与排序（决定先探索谁）（`7a85ecc`）

### 第 4 层：测试流量污染生产（贯穿第 1 轮）

- 详见第 1 轮记录（`X-CA-Test-Mode` 头契约 + 三边界残留守卫 + 791 节点 KG 清理）

## 三、loop 自我评估（修订步骤）

**做对了**：
- 不满足于"症状消除"——第 1 轮声称修好，仍不探索，继续深挖到 4 层根因
- 每层都用**实测**确认（py-spy 栈、概念提取输出、value 计算、端到端日志）
- 每层都加回归护栏，锁死不复发

**关键教训**：
- **"修完一个 bug 就以为好了"是最大的陷阱**。第 1 轮修 EmbeddingService 后日志确实变了，
  但真问题是"tick 永不返回"——症状消失 ≠ 根因清除。
- **静默失败有多层**：tick 不返回是"线程级静默"；去重误合并是"语义级静默"；冲突否决是
  "数值级静默"。三者都不报警，都表现为"系统看起来正常"。
- **符号级去重的脆弱性**：单字/超通用词必然导致跨域误合并。去重必须基于具区分度的概念。
