## 二、根因分析（本轮核心产出）

### 2.1 一条被忽视的完整污染链

```
legacy_tests_v026/e2e/test_cognitive_loop.py   （打 live API）
  → POST /api/knowledge/check {topic: BrandNewTopicXYZ123}
  → 路由 record_gap(observed_by 默认 'hook')
  → real_seen=1（测试伪装成真实观测！）
  → _enqueue_gaps 提升为 deep_read 任务
  → 测试话题进入真实探索队列 + 写入 Neo4j KG
```

**实测证据**：gaps 表被 `BrandNewTopicXYZ123` / `UnknownTopic123` / `量子计算xyz` / `never-worked` / `FreshSyntheticCheckXYZ999` 污染，全部 `real_seen=1, observed_by='hook'`。

### 2.2 架构缺陷层次

| 层 | 缺陷 | 修复 |
|----|------|------|
| 表现层 | `queue empty` 日志说谎 | D-1：区分真空/被排除 |
| 失败可见性 | DeepRead 失败走 DEBUG + 不标记 | D-2：WARNING + failed_reason |
| 发动机 | EmbeddingService 缺 config | D-3：传 config |
| 入队谓词 | 无残留判定 | D-1b：`_is_residue_topic` 三边界拦截 |
| **隔离边界** | **测试流量伪装成真实观测** | **D-1c：X-CA-Test-Mode 头契约** |
| 数据层 | 526 个测试节点直写 KG | scrub 脚本清理 |

### 2.3 关键教训（可复用）

1. **名称启发式挡不住任意合成名**。`_is_residue_topic` 拦不住 `FreshSyntheticCheckXYZ999`——**必须用显式测试标记（header）作权威信号**，名称只作兜底。
2. **同一逻辑的两处调用点必须同时改**。初版只改了 `/kg/confidence`（唯一出口），漏了 legacy `/knowledge/check` → 实测发现。教训：grep 全部调用点。
3. **静默失败的最贵形态是"日志说谎"**。`Enqueued orphan node` 在 dedup 跳过时仍打印——与 `queue empty` 同类。已在 `_scan_orphan_nodes` 修复为真实计数。
