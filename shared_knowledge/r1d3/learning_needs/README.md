# learning_needs — R1D3 显式学习需求

> **C2-B (v0.3.6)** · 决策：weNix 2026-10-08

## 这是什么

**R1D3 主动声明**「我想学 X」的地方。

用户只与 R1D3 交互，不与 CA 直接交互。因此"系统想学什么"这个意图，
**只能由 R1D3 声明**——CA 不"从对话推断"（那是读心，违反 C1 公理）。

## 由谁写

**R1D3 写**（通过 `POST /api/knowledge/learning_needs`）。
**CA 只读**（作为缺口相关性的第三信号）。

## 文件格式

每个文件 = 一条需求，文件名 = `<slug>.md`：

```markdown
---
topic: FlashAttention
priority: high
created_at: 2026-10-08T21:43:00+00:00
updated_at: 2026-10-08T21:43:00+00:00
---
为什么想学：用户连续问了 3 次注意力优化，系统无对应知识。
```

- `priority`：`high` (权重 1.0) / `normal` (0.7) / `low` (0.4)
- 正文：为什么想学（供人类/LLM 阅读，CA 不解析）

## CA 如何使用

`gap_calculator` 的相关性 = `max(会话触发, 显式需求权重)`：

- 显式需求 = 最强意图信号（R1D3 主动）
- 会话触发 = 隐式频次（用户问了几次我却没有）
- **取 max 而非相加**，避免双重计票

作用：有显式需求的 topic，即使没人问过，缺口优先级也会被拉高 → 主动探索。

## 何时写

**只在 R1D3 确实判断"这个值得补、但现在没有"时写。** 不要滥用：
- ✅ 用户反复问但系统无知识
- ✅ 系统自知边界缺口且对当前任务重要
- ❌ 一次性的普通查询
- ❌ 纯测试/演示

## 目录约定

`shared_knowledge/r1d3/learning_needs/<slug>.md`
（slug 保留中英文，其余字符折叠为 `_`）
