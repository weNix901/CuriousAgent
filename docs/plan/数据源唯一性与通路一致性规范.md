# 数据源唯一性 & 消费通路一致性 — 审计与规范

> **来源指令**：weNix，2026-10-08
> **纪律**：做改动时**保持数据源唯一性**，**保持消费通路一致性**。
> **禁止**：新增一个消费逻辑的同时还留着旧通路 → 两套逻辑并存 → 不一致。
> **性质**：本文件是**硬约束**，适用于 CA 后续所有开发（v0.3.6 及以后）。

---

## 〇、核心原则

> **每个概念只有一条写入通路、一条读取通路。新增通路必须同时废除旧通路，不得并存。**

这条原则是 `next_move_v0.3.6_SSOT.md` 的延伸：SSOT 解决的是"**读到哪个源**"，
本原则解决的是"**走哪条路写**"。两者缺一，系统就会重新长出静默失败。

---

## 一、真源与写入通路裁定表

| 概念 | 唯一真源 | **唯一写入通路** | **唯一读取通路** |
|------|---------|----------------|----------------|
| 知识 / 质量 / status | Neo4j | `add_to_kg` / `update_kg_status` | `get_kg_factory().get_node_sync()` |
| dormant | Neo4j | `kg.mark_dormant()` | `get_dormant_nodes()` |
| 探索队列 | queue.db | `kg.add_curiosity()`（带去重） | `QueueStorage.get_pending_items()` |
| 缺口 | ops.db.gaps | `gap_store.record_gap()` | `gap_store.list_gaps()` |
| 缺口消费标记 | ops.db.gaps | `gap_store.mark_consumed()` | `gap_store.reset_stale_consumed()` |
| 检索命中 | ops.db.retrieval_events | `retrieval_store.record_retrieval()` | `retrieval_store.list_retrievals()` |
| meta_cognitive | ops.db.meta_cognitive | `update_meta_exploration()` | `get_meta_cognitive_state()` |
| 运行时开关 | ops.db.runtime_kv | `set_search_exhausted()` 等 | `is_search_exhausted()` 等 |

**规则**：任何功能新增，若对应概念已有通路，**必须复用**，不得另起一条。

## 二、审计发现（2026-10-08）

### 2.1 已修复：相关性因子旧通路并存

**问题**：`gap_calculator.rank_gaps()` 曾写"回退：real_seen 缺失时用 seen_count"。
这是**典型的新旧通路并存**——新通路（real_seen 去噪）+ 旧通路（seen_count 混噪声）同时活着。
在 `feedback_store` 等调用方传完整 gaps 行时能触发回退。

**修复**：删除回退，**只认 real_seen**，缺失即视为 0（"缺值 = 无真实观测"，非"用旧值"）。
唯一通路：`record_gap(observed_by=...)` 维护 real_seen → `rank_gaps` 只读 real_seen。

### 2.2 队列写入旁路（**✅ C2b 已收敛，2026-10-08**）

当前 queue.db 有 **9 处直接 `QueueStorage.add_item()`** 绕过 `add_curiosity()`：

| 位置 | 用途 | 是否绕过去重 |
|------|------|-------------|
| `explore_agent.py:704` | deep_read 任务入队 | ✅ 绕过 |
| `dream_agent.py:375/394` | 梦境候选入队 | ⚠️ 自带 pending 去重（弱于 add_curiosity） |
| `daemon/dream_daemon.py:82` | L4 topic 入队 | ✅ 绕过 |
| `hooks/cognitive_hook.py:224` | 认知钩子入队 | ✅ 绕过 |
| `api/host_agent_integration.py` (间接) | 宿主注入 | 走 add_curiosity ✅ |
| `curious_api.py:654` | Web UI 注入 | ✅ 绕过 |
| `curious_api.py:2201` | API 队列注入 | ✅ 绕过 |
| `tools/web_scrape_tools.py:119` | 抓取后入队 | ✅ 绕过 |
| `knowledge_graph_compat.py:350` | add_curiosity 内部 | ✅ 规范入口本身 |

**风险**：`add_curiosity()` 做**跨库去重**（`concept_normalizer` 比对 KG + 队列）。
绕过它的旁路会**重复入队**（同义 topic）→ 队列膨胀 + 探索资源浪费。

**处置结果（C2b，2026-10-08 已实施）**：

| 原旁路 | 处置 | 状态 |
|--------|------|------|
| `dream_agent.py:375/394` | 改走 `add_curiosity()` | ✅ 已收敛 |
| `daemon/dream_daemon.py:82` | 改走 `add_curiosity()` | ✅ 已收敛 |
| `hooks/cognitive_hook.py:224` | 改走 `add_curiosity()` | ✅ 已收敛 |
| `curious_api.py:654` | 改走 `add_curiosity()` | ✅ 已收敛 |
| `curious_api.py:2201` | 改走 `add_curiosity()` | ✅ 已收敛 |
| `tools/web_scrape_tools.py:119` | 改走 `add_curiosity()` | ✅ 已收敛 |

**收敛后**：`queue.db` 写入通路 = `add_curiosity()`（唯一）
+ deep_read 任务（登记例外）。`add_item` 调用点仅剩 2 处（入口自身 + 例外）。

### 2.3 已确认干净

- **gaps 表**：无旁路直写（无 `INSERT INTO gaps` / `UPDATE gaps` 散落代码）
- **dormant**：SSOT-1 后只有 `kg.mark_dormant()` 一条写入路径
- **queue.db**：无旁路 `INSERT INTO queue` / `UPDATE queue`（全部经 QueueStorage 方法）

## 三、新增功能的准入检查（Checklist）

任何新增消费逻辑，提交前必须逐条通过：

```
[ ] 1. 该概念是否已有真源？→ 有则复用，不得新建
[ ] 2. 是否新增写入通路？→ 若是，旧的写入通路是否同批废除？
[ ] 3. 是否新增读取通路？→ 若是，旧读取通路是否同批废除？
[ ] 4. 新通路与旧通路是否会产生不一致输出？→ 是则禁止并存
[ ] 5. 失败是否可见？（不得 catch{} 静默）
[ ] 6. 是否在本文档的真源/通路表登记？
```

**违反示例（反面）**：新增 `feedback_lookup` 提权逻辑，同时保留原 `seen_count` 相关性
→ 两条相关性通路并存 → 排序结果不可解释。

## 四、与 SSOT 批次的关系

```
SSOT-0..6        解决"读到哪个源"（读通路唯一）
本规范（通路审计）  解决"走哪条路写"（写通路唯一）
                 ↓
           两者共同构成"唯一真源 + 唯一通路"的完整地基
```

**执行顺序**：第 2.1 已修复；第 2.2 队列旁路收敛（**C2b**）已于 2026-10-08 完成。
