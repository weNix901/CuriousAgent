## 二、❌ 项根因分析

### A-1 — `merge_nodes` FOREACH MERGE 搬运关系不带 key

节点合并（`merge_nodes`）时把 `other` 的关系搬到 `target`，用
`MERGE (target)-[type(rel)]->(endNode(rel))` —— **按 relationship-type 匹配，不带 key 属性**。
这正是 v0.3.7 §四.1 表格里标注的「未带 key」路径。

**风险**：绕过了「属性级唯一约束」（约束建立在 `r.key` 上），批量合并时可能产生重复搬运边。
**修法**：搬运时用 `SET` 补写 `key` 属性（key = `<from>|<type>|<to>`），并对目标边 MERGE on key。

### A-2 — `migrate_state_to_neo4j._create_relation` 不带 key

迁移脚本 `MERGE (a)-[:{rel_type}]->(b)` 无 `key`。
**现状**：脚本已无源（`state.json` 已退场，SSOT 迁至 Neo4j），属历史路径，但仍在仓库。
**修法**：补 key（或直接改调 `add_relation`）；并给 `backfill_relation_keys.py` 加 `--verify` 模式。
